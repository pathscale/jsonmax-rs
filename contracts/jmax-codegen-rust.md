# jmax-codegen-rust: frozen Wave 0 contract

Owner: W0-ROOTS-5, row 25. Source of truth:
`crates/jmax-codegen-rust/src/lib.rs`. Public modules: models, endpoints,
registries, compat. Allowed dependencies: jmax-abi, jmax-endpoint-model,
jmax-schema-aot, jmax-encode. The generator itself supports alloc without std.
It returns source artifacts in memory, performs no filesystem writes, invokes
no external tool, and never changes a caller's model.

## Root definitions and exports

Public Error/ErrorCode/ErrorSource/Result are canonical ABI types. EndpointField,
EndpointModel, EndpointSchemaSpec, EndpointType, EnumVariantSpec, ErrorSpec,
HeaderSpec, ModelVersion, RoleSpec, ServiceSpec, TypeDefinition are re-exported
from endpoint-model without copying their definitions into this crate.

```rust
pub const CONTRACT_VERSION: u16 = 1;
pub const GENERATED_NOTICE: &str = "// Generated by jmax-codegen-rust. Do not edit.\n";
pub enum CompatibilityMode { Native, LegacyV1, LegacyV2 }
pub struct CompatibilityOptions {
    pub mode: CompatibilityMode, pub emit_definition_variants: bool,
}
pub struct CodegenOptions {
    pub module_name: String, pub abi_path: String, pub aot_path: String, pub derive_path: String,
    pub emit_views: bool, pub emit_schema_tables: bool, pub compatibility: CompatibilityOptions,
}
pub enum ArtifactKind { ModuleRoot, Models, Endpoints, Registries, SchemaTables, Compatibility }
pub struct GeneratedArtifact { pub path: String, pub contents: String, pub kind: ArtifactKind }
pub struct RegistryArtifacts { pub registries: GeneratedArtifact, pub schema_tables: GeneratedArtifact }
pub struct Generation { artifacts: Vec<GeneratedArtifact> }
pub enum RustTypeMode { Owned, View }
pub struct RustType { pub source: String, pub needs_lifetime: bool }
```

String/Vec are alloc types. All owning records are Clone + Debug + PartialEq + Eq.
Generation additionally implements Default with an empty private vector. The
three small enums are Clone + Copy + Debug + PartialEq + Eq; ArtifactKind also
has PartialOrd + Ord in declaration order. CompatibilityMode defaults to Native;
CompatibilityOptions defaults to Native/false. CodegenOptions defaults to
module_name generated, abi_path ::jmax_abi, aot_path ::jmax_schema_aot,
derive_path ::jmax_derive, emit_views true, emit_schema_tables true, and default
compatibility. A configured derive crate is a dependency of the generated
consumer when derives are emitted, not an added dependency of this generator.

```rust
impl Generation {
    pub fn artifacts(&self) -> &[GeneratedArtifact];
    pub fn into_artifacts(self) -> Vec<GeneratedArtifact>;
    pub fn insert(&mut self, artifact: GeneratedArtifact) -> Result<()>;
}
pub fn validate_artifact_path(path: &str) -> Result<()>;
pub fn validate_options(options: &CodegenOptions) -> Result<()>;
pub fn rust_string_literal(text: &str) -> String;
pub fn generate(model: &EndpointModel, options: &CodegenOptions) -> Result<Generation>;
pub(crate) fn codegen_error(code: ErrorCode, detail: &'static str) -> Error;
```

Generation stores artifacts in bytewise path order. insert validates the path,
requires contents to start with GENERATED_NOTICE, and rejects both exact and
ASCII-case-insensitive destination collisions. On failure the collection is
unchanged. Paths are nonempty relative forward-slash paths ending in .rs, with
no empty/dot/parent components, backslashes, control/non-ASCII bytes, colon or
Windows-reserved punctuation, trailing dots, or reserved device stems CON/PRN/
AUX/NUL/COM1..9/LPT1..9. Components use only ASCII letters/digits/_/-/dot.
The in-memory path validation does not claim to protect a later filesystem
writer against symlinks; that writer has its own destination contract.

validate_options uses AOT validate_symbol for module_name, checks its prospective
module-root path for portable components, and uses validate_rust_path for each
configured crate path. Paths are not arbitrary expressions. String
literal emission delegates to AOT rust_string_literal; user names/descriptions
must never be directly interpolated inside Rust literals or comments. Nonempty
raw identifier emission is a separate identifier operation, not string escaping.
All local errors use ABI Error with SchemaCompile source and byte_offset 0;
known schema/field ids are attached by wave functions. Dependency errors are
propagated without flattening their code/source/context.

## Root orchestration and artifact namespace

The implemented generate function validates options and constructs an
endpoint-model registry before calling models, endpoints, registries, compat in
that order. It inserts both registries outputs, then emits the module root.
Failure discards the local Generation; no partial plan is returned. Each wave
function must also validate its own input/options because it is independently
public and callers can bypass generate. Validation does not authorize silently
rewriting the model.

For module_name M, output paths and kinds are exactly:

| Path | Kind | Producer |
| --- | --- | --- |
| M/mod.rs | ModuleRoot | root |
| M/models.rs | Models | models |
| M/endpoints.rs | Endpoints | endpoints |
| M/registries.rs | Registries | registries |
| M/schema_tables.rs | SchemaTables | registries |
| M/compat.rs | Compatibility | compat |

All six are returned even for an empty model or Native mode. Empty catalogs are
complete valid Rust with explicit zero-length tables, not missing artifacts.
The root module contains `extern crate alloc;` and public declarations for the
five sibling files. Child generated source uses `super::alloc` for allocation
types or a local `use super::alloc;` so a nested generated module does not assume
a crate-root alloc import. Sibling references use super::models, super::endpoints,
super::registries, super::schema_tables, or super::compat, never absolute paths
containing a guessed host crate name. M controls directory placement, not an
extra nested wrapper in every file. CLI callers can use M=rust to obtain its
required Rust artifact paths, including rust/schema_tables.rs.

All output is UTF-8 with LF endings and exactly one trailing LF. No timestamps,
source-machine paths, random seeds, environment-derived values, Debug output of
model values, or map iteration accidents enter source. Preserve canonical model
field/service/variant order unless an explicit registry sorting rule applies.
Generated Rust must compile without unused lifetimes, unresolved cross-file
names, ownerless references, or orphan trait implementations.

## Wave 1: src/models.rs

```rust
pub fn generate_models(model: &EndpointModel, options: &CodegenOptions) -> Result<GeneratedArtifact>;
pub fn rust_type(ty: &EndpointType, mode: RustTypeMode, options: &CodegenOptions) -> Result<RustType>;
```

Generate every top-level definition and every inline nominal Struct/Enum used by
any definition, request, response, header, or stream type. Traverse finitely;
validate and intern names through canonical nominal reference rules. Reject
collisions after Rust PascalCase conversion, including collisions with generated
support types, rather than renaming public types unpredictably. Field Rust
identifiers are snake_case; preserve original wire names separately in generated
encoders/metadata. Escape legal keyword fields using raw identifiers; names that
cannot be raw identifiers (self, Self, super, crate, _) are errors. Do not alter
wire names to solve Rust name collisions. Definitions use public fields and
Clone + Debug + PartialEq where supported; do not derive Eq for floats.

Owned mapping: UInt32=u32, Int32=i32, Int64/TimeStampMs=i64, Float64=f64,
Boolean=bool, String/UUID/NanoId/IpAddr/blockchain address/hash=alloc String,
Bytea=alloc Vec<u8>, BlockchainDecimal=canonical ABI Decimal128, Unit=(),
Vec(T)=alloc Vec<Owned(T)>, Optional(T)=Option<Owned(T)>. Nominal Struct is its
PascalCase type; StructRef/StructTable are Box<PascalCase target> to keep recursive
models sized. Enum/EnumRef use their generated enum type; prefixed_name affects
legacy compatibility metadata only, never the canonical wire discriminant.

Generate nominal enums with explicit i32 discriminants, declaration-order
variants, and #[repr(i32)]. Their JsonEncode emits their numeric value, not a
variant name. Empty enum definitions and duplicate output names/discriminants
must be explicit ConstraintViolation errors. Scalar/container alias definitions
use a public type alias and must not trigger forbidden foreign-trait impls.

Object maps to generated `models::JsonObject`, which owns ordered `(String,
JsonValue)` pairs; generated JsonValue has Null, Bool(bool), U64(u64), I64(i64),
F64Bits(u64), String(String), Array(Vec<JsonValue>), Object(JsonObject) variants.
Emit these support types only when Object occurs, and reserve their names when
needed. Their recursive JsonEncode preserves order, rejects duplicate object
keys and non-finite numbers, and propagates sink failures. No unvalidated raw
fragment masquerades as Object. Use bounded iterative traversal or an explicit
generated depth ceiling of 128 for recursively encoded containers/nominal
references; return DepthLimitExceeded before overflowing the host stack.

All nominal records get canonical JsonEncode implementations. Use AOT typed
writers for primitives and generated implementations for nominal values; no
assumption that foreign primitives already implement the ABI trait. Bytea emits
canonical padded standard base64. Enum emits i32. Optional absent fields are
omitted from records; Optional values inside arrays emit null. Unit emits null.
Decimal uses exact AOT decimal writing. NanoId/UUID/IP/address/hash string wrappers
preserve contents; payload validation remains a schema/decoder operation.

When emit_views, generate `<Name>View<'a>` for every nominal record and enum. Each
is a checked Rust borrow wrapper with a private `value: &'a Name`, `pub fn new(value:
&'a Name) -> Self`, and `pub fn value(&self) -> &'a Name`. For records also expose
borrowed field getters using rust_type(View); enum views expose value(). Views
borrow existing typed owners; they do not claim to parse JSON or mint proofs.
Their JsonEncode delegates to the owner. There are no self-referential fields.

rust_type Owned returns the mapping above with needs_lifetime=false. View returns
copy scalar types for numeric/bool/Decimal/Unit, &'a str for string-like values,
&'a [u8] for Bytea, &'a [Owned(T)] for Vec, Option<View(T)> for Optional, and
<Name>View<'a> for nominal types and refs (dereferencing a Box when needed).
Object View is &'a JsonObject. needs_lifetime indicates whether the returned
source mentions 'a. Configured crate paths are validated; output uses sibling
models paths consistently even when called by endpoints. Alias-only cycles are
errors; recursive nominal definitions terminate traversal by visited name.
rust_type is syntactic and cannot resolve a nominal target without a model;
generate_models validates all targets through the registry first.

## Wave 2: src/endpoints.rs

```rust
pub fn generate_endpoints(model: &EndpointModel, options: &CodegenOptions) -> Result<GeneratedArtifact>;
```

For every endpoint generate `<ServicePascal><EndpointPascal>Request` from params
and `<ServicePascal><EndpointPascal>Response` from response in endpoints.rs. Use
owned field mappings and JsonEncode behavior identical to models, including
empty-object encoding for empty request/response records. No envelope fields
are invented in these payload structs. For a stream_response emit a public
`<ServicePascal><EndpointPascal>Stream` alias with its owned mapping; omit it when
None. With emit_views add owner-borrowing request/response wrappers with the same
new/value contract as model views. Reject all transformed-name collisions.

Each request type has these inherent constants:

```rust
pub const CODE: u32;
pub const METHOD: &'static str;
pub const ROLES: &'static [&'static str];
```

CODE preserves endpoint.code, METHOD is exact canonical service.endpoint, and
ROLES preserves required roles in declaration order. A stream alias does not
promise transport/framing behavior. There is no invented ABI Endpoint trait.

Generate one `pub enum EndpointError` with fieldless known variants named from
ErrorSpec.name plus `Unknown { code: u32, message: String }`. The Unknown name is
reserved; reject transformed collisions with it. Known variants preserve exact
codes/messages. Expose `pub fn code(&self) -> u32` and `pub fn message(&self) -> &str`.
Its JsonEncode is the exact object {"code":<number>,"message":<string>} using AOT
writers and correct escaping. An empty known error list still has Unknown.
Errors are model-global; do not invent endpoint-specific allowed-error sets.

When emit_schema_tables, eligible flat record types also implement SchemaProvider
and JsonDecode using the exact schema/slot identities produced by registries.
Decode by checked AOT access, checked u32/i32 narrowing, owned string copies,
and canonical base64 decoding for Bytea. Omitted optional fields become None;
explicit null is rejected by the generated schema. Decoding checks proof owner
lengths, fingerprint, exact slot count, requiredness, and field types. All code
paths return ABI Result. Ineligible compound/decimal/enum fields cause
UnsupportedSchemaFeature when tables are requested; do not generate an empty or
weaker decoder. When emit_schema_tables=false, emit encoders and owner views
without claiming a SchemaProvider/JsonDecode implementation. Model nominal
records follow the same rule; scalar and enum types have no fabricated flat
object schema. Never use the limited derive parser to encode unsupported
compound fields: emit the concrete complete implementation directly.

## Wave 3: src/registries.rs

```rust
pub fn generate_registries(model: &EndpointModel, options: &CodegenOptions) -> Result<RegistryArtifacts>;
```

Return both named artifacts. registries.rs defines these generated metadata
records and tables (static UTF-8 strings/slices, no runtime hash maps):

```rust
pub struct TypeEntry { pub name: &'static str, pub schema_id: Option<u32>, pub fingerprint: Option<u64> }
pub struct EndpointEntry {
    pub code: u32, pub method: &'static str, pub roles: &'static [&'static str],
    pub request_schema: Option<u32>, pub response_schema: Option<u32>,
}
pub static TYPES: &[TypeEntry];
pub static ENDPOINTS: &[EndpointEntry];
pub fn type_by_name(name: &str) -> Option<&'static TypeEntry>;
pub fn endpoint_by_code(code: u32) -> Option<&'static EndpointEntry>;
```

TYPES covers declared top-level and interned nominal model types, sorted by
original qualified model name bytes. ENDPOINTS is sorted by code. Lookup uses
that sorting deterministically. Roles and methods agree with request constants.

Schema candidates are every nominal Struct plus each request/response record.
Qualified schema names are `model::<OriginalName>`,
`request::<OriginalService>.<OriginalEndpoint>`, and
`response::<OriginalService>.<OriginalEndpoint>`. Sort those names bytewise and
assign SchemaId 1..=N with checked u32 conversion. FieldId and slot index are
dense original declaration order. Generate all candidate IR through
endpoint-model::utilities::schema_for_fields with reject_unknown=true and
compile with AOT compile_schema. Fingerprints come from the authoritative IR
canonicalizer, identical to compiler header values. Model/endpoint emitters
compute exactly the same assignment; no independent hash-based id assignment.
They may share local pure logic by calling public APIs, but must not call each
other's generate functions recursively.

schema_tables.rs contains complete static source from AOT tables::emit_program
for each candidate, using symbols `SCHEMA_<id>`. Both projection static and
SCHEMA_<id>_PROGRAM bytes are present. Generated provider schema_ir() reconstructs
the corresponding canonical ABI IR and schema_fingerprint() returns its
precomputed constant. Full executable programs are obtained through the AOT
load_program facade; matching a table fingerprint alone is not an executable
witness. No omitted constraint/pattern/state side tables.

With emit_schema_tables=false, schema_tables.rs contains the generation notice
and an explicit `pub const SCHEMA_COUNT: usize = 0;`; all optional schema ids and
fingerprints in registries are None, and generated payloads do not claim decoding
support. With tables enabled SCHEMA_COUNT equals the complete candidate count.
An unsupported candidate fails the entire generation, never just that entry.
Use Option metadata instead of a magic zero fingerprint. No orphan trait impls
for primitive aliases, and no fabricated SchemaProvider for enum wire scalars.

## Wave 4: src/compat.rs

```rust
pub fn generate_compat(model: &EndpointModel, options: &CodegenOptions) -> Result<GeneratedArtifact>;
```

Always emit compat.rs with canonical metadata:

```rust
pub const LEGACY_VERSION: Option<u16>;
pub const MODEL_VERSION: (u32, u32, u32);
pub const DEFINITION_VARIANTS: &[(&'static str, &'static [(&'static str, i32, &'static str)])];
```

Native LEGACY_VERSION=None; LegacyV1=Some(1); LegacyV2=Some(2).
MODEL_VERSION preserves all three model components. Validate requested legacy
mode with endpoint-model legacy::export_legacy so V1 cannot discard role
inheritance/descriptions, errors, or headers. Canonical wire keys, endpoint codes,
enum numeric values, and fingerprints remain unchanged by mode. Emit legacy
aliases only when they can resolve unambiguously to the canonical generated
item; transformed aliases that collide return ConstraintViolation.

When emit_definition_variants, populate DEFINITION_VARIANTS with all nominal
enums, original model name followed by declaration-order (wire name, i32 value,
description) tuples, sorted by model name. Models emit matching inherent
JMAX_DEFINITION_VARIANTS constants, following the DefinitionVariant derive bridge.
When false DEFINITION_VARIANTS is an explicit empty slice and no bridge constants
are added. A scalar numeric enum with non-ASCII descriptions remains supported
through string escaping. Legacy integration never adds an unlisted serialization
crate, unconfigured derive, or guessed external trait. Compatibility flags control
only documented artifact content, not validation bypasses.

## Cross-module invariants and errors

Every requested artifact is complete, deterministic, and mutually resolvable.
The root alone orchestrates all four emitters; direct emitters return only their
assigned artifacts and do not write sibling files. Shared naming/type mapping
may use public rust_type and endpoint-model wire helpers; canonical schema
construction uses the same endpoint-model utilities and AOT facade. Shared
schema-id assignment must be implemented consistently in each emitter without
requiring root edits or new files. No module calls root generate.

Name/path/output collisions are ConstraintViolation; resource/count overflow is
BudgetExhausted; unsupported schema/legacy projections are
UnsupportedSchemaFeature. Malformed source parameters fail before interpolation.
Generated encode/decode errors use Encode/Decode source respectively and
propagate sink or checked-reader errors. No generator or generated view issues
ValidationProof. A consumer may trust full programs only after the compiler
validator constructs ValidatedProgram; StaticSchemaImage is merely a projection.
