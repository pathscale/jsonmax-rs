# L1 Handoff: `ps-rusty_alloc` Executable Integration

Implemented the Wave 6 Section 7 executable allocator integration in the eight owned source/manifest files.

## Changes

- `crates/jmax-bench/Cargo.toml`: added `rusty_alloc.workspace = true` and the empty `system-alloc` feature. The default feature set remains unchanged, so the benchmark uses RustyAlloc by default.
- `crates/jmax-bench/src/bin/jmax_bench.rs`: added one `#[global_allocator]` counting wrapper. In the default configuration it delegates `alloc`, `dealloc`, `alloc_zeroed`, and `realloc` to `rusty_alloc::RustyAlloc`; with `system-alloc`, those methods delegate to `std::alloc::System`. The output header reports the selected allocator and aggregate allocation/deallocation calls. No benchmark algorithms were changed.
- `crates/jmax-validator/Cargo.toml`: added the workspace `rusty_alloc` dependency.
- `crates/jmax-validator/src/main.rs`: installed `rusty_alloc::RustyAlloc` as the executable's single global allocator.
- `crates/jmax-runner/Cargo.toml`: added the workspace `rusty_alloc` dependency.
- `crates/jmax-runner/src/main.rs`: installed `rusty_alloc::RustyAlloc` as the executable's single global allocator.
- `crates/jmax-gen-cli/Cargo.toml`: added the workspace `rusty_alloc` dependency.
- `crates/jmax-gen-cli/src/main.rs`: installed `rusty_alloc::RustyAlloc` as the executable's single global allocator.

The benchmark counting wrapper uses unsafe `GlobalAlloc` delegation, so the binary-level `forbid(unsafe_code)` attribute was replaced with `deny(unsafe_op_in_unsafe_fn)`; every allocator call is inside an explicit unsafe block.

## Verification

Inspected the Wave 6 plan's Section 7 and `reports/wave6/CONTRACTS.md`. Reviewed the changes and confirmed each executable source declares one global allocator. No `cargo` or `rustc` commands were run, as required; workspace compilation is left to the coordinator.
