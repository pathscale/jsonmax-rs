## Delivered changes

### Escape discovery classifies each block at most once per traversal

Added `jmax_string::EscapeMaskCursor` in `src/masks.rs`. It binds its input and maintains `block_base`, `block_end`, and `escape_or_control_mask`. Blocks are aligned, nonoverlapping 64-byte ranges. Full blocks are classified directly through a cached `EscapeMasker`; short tails build one bounded scalar mask without padding or staging copies.

After advancing across a short escape, Unicode escape, or surrogate pair, discovery clears consumed bits with `mask &= u64::MAX << relative_position`. This is equivalent to clearing the low bits while avoiding a shift by 64. Remaining matches use `trailing_zeros()`. An exhausted mask advances to the next block; an escape crossing a boundary skips its consumed prefix without revisiting an earlier block. Ordinary runs continue across blocks, so mask boundaries cannot split an ordinary UTF-8 scalar.

Applied the cursor to:

- `decode_escaped_slice_into`, preserving its append checkpoint, length checks, UTF-8 error ordering, and transactional rollback.
- The syntax cursor's `decode_content`, replacing repeated `first_special(tail, dispatch)` searches. Its `EscapeMasker` is cached per complete-input cursor/cache rather than rediscovered after every escape.
- Legacy string boundary discovery (`scan_string`), decoded-length measurement, and both legacy unescape passes. Legacy sink validation still completes before reservation/emission; each required pass has its own cursor.

The standalone stateless finder APIs and serialization-policy behavior remain compatible. The original complete-input classification pass remains: this eliminates repeated decoder-helper classification, not all discovery/decoding passes. The historical 8,154-byte/129-helper-block probe was not rerun; no measured speedup or replacement byte count is claimed.

### Strict discard reuses state across subtrees and documents

The existing internal discard frame/table vectors are now exposed through public `jmax_syntax::SkipScratch` (`Debug + Default`), also re-exported by `jmax_cursor`. Added:

```rust
BlockCursor::with_scratch(
    input,
    limits,
    numeric,
    duplicate_owner,
    &mut skip_scratch,
)
```

The cursor borrows the scratch and returns its skip frame and per-depth duplicate-table capacities automatically on drop, including error paths. `BlockCursor::new` retains the same existing API and reuses its internal capacities across skips within that cursor. `SyntaxState` retains its existing scratch handoff and reuse across complete-input resets.

No per-skip frame/key-table vectors are allocated once the retained capacities cover the encountered shape. New or larger nesting/object shapes may still grow them. Retained duplicate entries contain offsets and hashes, not input owners or string bytes.

Discarded non-key strings, and keys when duplicate rejection is disabled, continue through the validating noncapture decoder without appending cooked bytes. For duplicate-sensitive escaped keys, each grammar frame now records a decoded checkpoint. Closing a discarded container reclaims its cooked keys immediately while leaving ancestor key bytes live. Reclaimed bytes are transferred into the cumulative discarded-byte counter, so physical reclamation does not bypass `max_decoded_bytes`. Whole-skip cleanup restores the caller's decoded entry checkpoint on success and failure. This bounds physical decoded retention by live open-container keys rather than all closed sibling objects.

The frame checkpoint adds one `usize` field to internal grammar frames; no extra checkpoint vector is allocated. Normal event-producing traversal continues retaining its emitted string references.

### Small hot methods and common tokens

Added inline hints to offset/peek/advance, failure helpers, refill/whitespace, byte expectation, string/key scanning, atom/number scanning, and low-bit masking. Tiny offset/peek/advance/low-bit methods use `inline(always)`; larger routines use `inline`.

Unescaped ASCII strings now return their borrowed metadata directly after the scanner proves closure, absence of controls/escapes/non-ASCII, and the raw string limit. This avoids a redundant checked content slice and generic UTF-8/error-arbitration path. Error cases and Unicode/escaped strings keep their validating paths.

Atom discovery now returns its already computed digit count. Plain grammatical integers with a valid number delimiter use that mask evidence instead of invoking a second byte lexer. Leading-zero forms, malformed boundaries, negative-zero policy failures, fractions, and exponents still use the established numeric validator. Digit limits retain their exact excess-byte offset. Integer overflow/conversion behavior remains the responsibility of the existing numeric conversion APIs.
