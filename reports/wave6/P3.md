## Retained query compilation and traversal

- `CompiledQuery` now retains its immutable `SelectorTrie` alongside the original ordered path strings. `compile_paths` builds the trie once; execution reads it directly. Cloning the compiled query clones its retained data, rather than deferring compilation to execution.
- `query::execute_borrowed` and the owned `query_payload` / new `execute` entry points perform no path parsing or trie construction. Repeated paths still have independent output vectors, in original caller order.
- Added `QueryScratch`, `execute_borrowed_with_scratch`, and owned `execute_with_scratch`. Scratch retains traversal frames, escaped keys, per-depth duplicate tables and P1's strict-discard storage. `recycle_borrowed` and `recycle_owned` reclaim match-vector capacities from a consumed result. Results do not borrow scratch.
- Queries without a terminal that is also a selector prefix use an iterative lexical `BlockCursor` traversal. Unselected values in query mode go directly to `skip_value(QueryOnly)`, before decoding scalar values or constructing container events/frames. Selected values receive `StrictValidate`. Strict queries use the same traversal with strict discard for every skipped value.
- Traversed objects retain decoded-key duplicate rejection with generation-based, per-depth open-addressed tables. Unknown keys inside structurally skipped interiors intentionally remain outside query-only validation. Scanned keys still enforce string limits; traversed containers enforce depth, member/item limits, delimiter order and EOF. Escaped key bytes remain in the arena for duplicate identity and cumulative decoded-byte accounting.
- Overlapping parent/descendant queries retain the existing event traversal and strict-subtree propagation. This preserves complete validation of a selected container while also extracting its descendants. That branch also uses the retained trie and reusable selector-frame storage.
- Query-only results always report `fully_validated == false` and gain no proof or capability.

No zero-allocation claim is made for cold query result storage, new shapes, growing duplicate tables, or results that callers do not recycle. Overlapping selection still has the event cursor's per-call setup costs. Selector edge lookup remains linear in the edges of the active selector node.

## Typed borrowed decoding without the payload copy

- Added `jmax_schema_aot::JsonDecodeBorrowed::decode_borrowed(BorrowedSlotReader)` and re-exported the trait from jsonmax. The already existing checked `SlotReader` / sealed `SlotSource` infrastructure supports owned slots, borrowed slots and scratch-borrowed slots.
- `JsonDecode` derives now generate the new trait implementation as well as the frozen owned ABI implementation. The owned implementation constructs its checked reader and delegates to the same field-decoding body. The borrowed implementation independently checks the expected schema fingerprint and slot count, and continues using the checked AOT scalar/string decoders.
- `parse::from_borrowed` and `from_borrowed_with_schema` no longer construct `Payload`, copy the input into a Vec, or synthesize an owned `ValidatedSlots`. They validate/extract directly from the original slice and invoke the borrowed reader.
- Added `from_borrowed_with_schema_into` for retained VM/slot/decoded storage. The temporary borrowed slot guard prevents scratch reuse during decoding; returned T must own any data it needs beyond that call.
- `from_borrowed` uses the existing per-type schema cache in std builds. Caller-compiled variants avoid that cache lookup. no_std still compiles the type schema in the convenience entry point; callers can retain a compiled schema to avoid that work.
- Internal all-slot typed selection is now represented by the VM's empty field list, eliminating dense all-field selection construction and per-decode all-field-to-slot resolution.
- Owned extraction in selection order, including the warm scratch variant, now truncates the existing result vector for an identity-prefix selection instead of allocating a second ordering vector. Arbitrary reordering retains the existing checked implementation.

### API migration

`from_borrowed` now requires `JsonDecodeBorrowed + SchemaProvider + 'static`; the `'static` bound enables the std type cache. `from_borrowed_with_schema` and its scratch variant require `JsonDecodeBorrowed + SchemaProvider` without a static bound. Derived types acquire the new implementation automatically. Handwritten types that implement only ABI `JsonDecode` must add the borrowed reader implementation to use these APIs; owned decoding entry points remain available with their prior ABI. No change to `jmax-abi` was required.

Owned String fields still allocate/copy their field contents as required by their Rust representation. Custom decoders may deliberately copy or retain owned data. The guarantee here is removal of the facade's unconditional whole-input payload copy, not zero allocations for arbitrary T or a new derive representation for borrowed string fields.

`crates/jsonmax/Cargo.toml` adds the existing workspace `jmax-schema-aot` dependency and forwards alloc/std features. **The coordinator must refresh the jsonmax dependency entry in Cargo.lock. P3 did not edit Cargo.lock.**

## VM allocation removal and retention

- `SelectionIndex` now has four inline u64 words. Explicit selection on programs with at most 256 slots needs no heap bitset, including standalone `SelectionIndex::new`. Larger selections continue using the existing retained `VmScratch::selection_words` allocation. Empty/all selection needs no populated bitset at any size. ID bounds, duplicate selected IDs and strict-selection checks remain enforced.
- `ObjectState` now keeps a single inline u64 membership mask for at most 64 **known keys**. Only wider tables allocate/reuse `seen_words`. Required-field checking and duplicate/captured-field checking use the same checked accessor over inline or wide storage.
- The inline threshold uses total known-key count rather than required-field count alone: optional known keys also need membership bits for duplicate rejection and preventing repeated captured writes. A schema with few required fields but more than 64 total known keys correctly takes the wide path.
- VM per-depth seen-mask storage is created/accessed only for wide objects. Unknown-key table storage is created/reset/taken only when duplicate rejection is enabled and the schema/runtime permit unknown keys, or when the object has no whitelist. Objects rejecting unknown keys need no unknown-key table; disabling duplicate rejection also avoids that table's pool and key storage entirely.
- Closing/recovering small or nontracking sibling objects no longer overwrites retained wide-mask or unknown-key storage with an empty placeholder. Active wide masks/tables return to their depth pool on successful close and on failures with an open frame.
- The direct VM already had the correct pre-frame `value_pending` branch for unconstrained unknown values / unconstrained Any states: it calls `BlockCursor::skip_value(StrictValidate)` in strict mode instead of building a VM frame/ObjectState. This was retained and audited; constrained known values still execute schema checks. Merely having seen known keys does not authorize ignoring required/type/count/unknown-key constraints.
- Added `ValidationScratch::direct_skip` and switched direct execution to P1's `BlockCursor::with_scratch`. Strict-discard grammar/duplicate storage is now retained across VM calls, including failures, instead of being dropped with each direct cursor. Query scratch uses the same P1 API.

The entry source already reused wide masks and unknown tables by depth; the remaining work was inline small-state storage, avoiding unused pools, preserving retained capacities, and retaining syntax discard buffers across calls. The historical allocation rows have **not** been remeasured, so this handoff does not attribute an exact count or claim a measured speedup. P1 also changes the discard consumer itself; the coordinator should assess combined allocation results.

The Stage 5 GitHub typed adapter builds a borrowed DOM and invokes owned extraction separately for each event object. That multiplies cold per-call VM frame/slot/result setup by the event count; it is not one VM run over the root array. The new inline state and prefix ordering optimization reduce those runs, but reusable frame/output storage requires callers to use the existing endpoint scratch APIs. The external adapter is outside P3 ownership and was not changed. Necessary owned output vectors/strings and the adapter's DOM costs remain real allocations; P2 owns the native DOM changes.

## Cross-worker integration dependency

P3 consumes P1's public `jmax_syntax::{SkipScratch, BlockCursor::with_scratch}` API now present in the shared tree:

```rust
BlockCursor::with_scratch(input, limits, numeric, duplicate_owner, &mut skip_scratch)
```

`SkipScratch` returns its retained storage automatically when the cursor drops. P3 changed no syntax/cursor files. Syntax skip-state storage remains governed by syntax limits; the VM's explicit heap accounting still covers its own frames, selection, masks, unknown tables, slots and decoded storage. There is no new public retained-byte accessor for syntax skip storage in this integration.
