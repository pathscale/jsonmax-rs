## Compiler changes

`image::validate` remains the sole `ValidatedProgram` constructor. Both `lower::compile` and `image::decode` reach it, so every witness receives the same immutable indexes once. The serialized image format/version does not change; derived indexes are not serialized.

New public types/functions/methods:

| API | Contract |
| --- | --- |
| `CompiledStateDispatch` | Prevalidated scalar-kind mask, unique incoming `slot_index`, direct and subtree slot/constraint flags, and whether unknown fields are unconstrained. Type restrictions count as schema constraints. Shared states can have multiple incoming capture slots; their `slot_index` is `None`, while `has_slots` remains true and field dispatch remains authoritative. |
| `scalar_kind_bit(ScalarKind) -> u8` | String=1, Number=2, True=4, False=8, Null=16. Container state masks are zero; Any accepts mask 31. Integer masks account for the compiled quoted-integer policy. |
| `ValidatedProgram::dispatch(StateId)` | Checked immutable per-state dispatch access. |
| `ValidatedProgram::parents(StateId)` | Checked immutable reverse schema edges, used to propagate query selection reachability once per run. |
| `ValidatedProgram::required_mask(table)` | Required membership in the same table-local bit numbering used by object duplicate tracking. |
| `keys::KeyMatch` | Collision-checked `index`, `local_index`, and copied ABI `entry`. |
| `keys::lookup_with_swar(&CompiledProgram, table_index, key_bytes, swar_head)` | Uses KeyMeta's already packed SWAR head. Retains bounded strategy probes, safe candidate indexing, and exact byte comparison. PHF seeds/hashes are unchanged and are not replaced with the unrelated duplicate hash. |
| `keys::lookup(&CompiledProgram, table_index, key_bytes)` | Convenience wrapper delegating to `lookup_with_swar`, computing a head only for callers without token metadata. |
| `keys::lookup_image(&SchemaImage, &KeyTable, key_bytes)` | Compatibility name for the former standalone image/table `lookup` signature. `lookup_unchecked_table` and `lookup_index` also remain available. No in-repository caller of the old `lookup` signature was found. |
| `patterns::is_match_validated(&ValidatedProgram, pattern_index, text, steps_left)` | Runs an immutable witnessed pattern without repeating structural program validation on every string. The existing raw `patterns::is_match` stays defensive. |

`ProgramIndexes` now owns dispatch summaries, reverse edges, and required masks alongside existing field-slot/table-state indexes. Subtree flags use iterative monotone propagation over reverse edges, including recursive graphs; no recursive schema traversal or per-document bytecode validation is needed.

## Direct VM and ownership

New `jmax_schema_vm::direct` module consumes `jmax_syntax::block_cursor::BlockCursor` lexically and drives its own grammar phase stored alongside the existing bounded VM frames. The complete-input engine does not construct an EventInput adapter, legacy Cursor, SyntaxState, event vector, token vector, or copied input Payload. `ValidationScratch` no longer constructs/stores a legacy Cursor.

The existing `EventInput`, `CursorInput`, `execute::run`, and `execute::validate` remain supported for streaming/custom sources. Their immutable instruction re-decoding/revalidation was also removed: validated StateKind/ConstraintSet/indexes are authoritative. Defensive token/string checks remain on the custom-event path.

Direct keys enter crate-private `objects::key_meta` using `KeyMeta::string.raw_token`, cooked StrRef, SWAR head, and cooked FNV-1a hash. They never invoke `next_key_token`, re-pack a SWAR head, validate key UTF-8 again, or count characters again. Direct scalar constraints use crate-private `check_scalar_trusted`; UTF-8 and scalar lengths come from private cursor metadata on these exact buffers. Public/event APIs remain checked. Raw pattern entry points remain defensive; witnessed scalar constraints use the new witnessed pattern execution entry point.

Duplicate policy:

- The direct cursor uses `DuplicatePolicyOwner::SchemaVm` when rejection is enabled, otherwise `Disabled`.
- Known keys use a single `seen_words` membership test/set. Precomputed required masks reuse those bits at close; missing-field diagnostics identify the first missing compiled field.
- Unknown keys use a collision-safe span-backed `UnknownKeyTable`, reusing KeyMeta's cooked hash without rehashing/copying. Standalone/event callers use the same FNV-1a hash when metadata is unavailable.
- Strict discarded subtrees delegate to BlockCursor's strict consumer. S2 has landed the required temporary Syntax duplicate ownership inside that consumer; the outer VM does not also traverse those keys.
- With duplicate rejection disabled, uncaptured known and unknown duplicates are allowed. An actually selected slot still cannot be written twice; extraction reports a capture constraint error rather than overwriting a prior selected value.

## Complete-input public APIs

Common argument order is `(program: &ValidatedProgram, input, [selection: &Selection], limits: VmLimits, numeric: NumericPolicy, [scratch: &mut ValidationScratch])`.

Strict validation only:

| API in `direct` | Input/result |
| --- | --- |
| `validate_borrowed` | `raw: &[u8]` → `(ValidationProof, ValidationCapability)` |
| `validate_borrowed_into` | Same, with retained scratch |
| `validate_payload_direct` | `payload: &Payload` → proof/capability bound to the exact retained Payload owner/range |
| `validate_into` | Same Payload validation with retained scratch |
| `policy_fingerprint` | Combines syntax limits/policies, requested numeric policy, VM work limit and VM scratch ceiling. The schema fingerprint separately binds compiled schema policy. |

Validation-only execution never reserves/populates SlotValue output storage or selection words. Previously retained capacities may remain in reused scratch but are cleared and charged. Number policy is enforced for all numeric tokens, including discarded values, and quoted numeric constraints enforce the runtime digit limit. Requested and schema numeric policies are intersected; quoted integers require both policies to permit them.

Strict extraction:

| API in `direct` | Result |
| --- | --- |
| `extract_borrowed<'a>` | `BorrowedValidatedSlots<'a>`; original `raw: &'a [u8]`, decoded `Vec<u8>`, compiled-indexed slots `Vec<SlotValue>`, proof and capability |
| `extract_borrowed_with_scratch<'raw, 'scratch>` | `BorrowedValidatedSlotsRef<'raw, 'scratch>`; raw borrows the input and decoded/slots borrow scratch, preventing scratch reuse while those references live |
| `extract_payload_direct` | Owned ABI `ValidatedSlots`, preserving the original Payload owner |
| `extract_payload_into` | `&ValidatedSlots` borrowing retained scratch; output invalidated on failure |
| `extract_validated_borrowed` | Re-extracts from a live `BorrowedValidatedSlots` guard; structural-only skips are available after exact input/schema/policy verification |

Top-level VM re-exports cover the main borrowed/owned strict and query APIs. Additional entry points are public through `direct`.

For compatibility, **`execute::validate_into` keeps its old six-argument slot-producing signature** and delegates to `direct::extract_payload_into`. The new top-level/`direct::validate_into` is the validation-only API and takes no Selection. Facade callers wanting slots can keep the old `execute` call or move explicitly to extraction.

Slot vectors remain indexed by compiled slot number, with Empty for absent/unselected fields. Existing `ValidationScratch::order_selection` remains available for facades returning caller-order selections.

Strict skip rules:

- `None` states and unconstrained Any states use `BlockCursor::skip_value(..., StrictValidate)`; a selected Any slot captures its complete raw span.
- Constrained unselected states still run their type, scalar/count, numeric, pattern, format, required and unknown-key checks.
- No structural-only query jump can produce a strict result.
- Warm scratch retains VM frames, masks, unknown-key tables, selection words, decoded arena and query reachability storage. Decoded capacity growth is charged as it occurs.

Capabilities and safe validated skipping:

A copyable bare pointer capability can outlive a borrowed input or be presented after its address is reused. Safe S4 APIs therefore do **not** accept a naked capability to bypass validation. `BorrowedValidatedSlots` privately retains the original immutable borrow even if its public `raw` field is rebound. `extract_validated_borrowed` uses that private live borrow and verifies the exact schema and all requested policies; a mismatch takes the full strict path. After that check it privately narrows the capability to schema-zero syntax scope and constructs the cursor without numeric rechecking, because the live guard already proves those exact numeric policies. This fits S2's current `ValidatedOwner` contract (syntax-scope capability, no independent numeric policy). Public proof/capability fields never authorize unchecked AOT access.

Query-only extraction:

| API/type | Contract |
| --- | --- |
| `extract_query_borrowed` | Returns `BorrowedQuerySlots<'a>` with original raw borrow, decoded output and compiled-indexed slots. |
| `extract_query_payload` | Returns owner-preserving `QuerySlots`. |
| `BorrowedQuerySlots` / `QuerySlots` | Deliberately contain no ValidationProof or ValidationCapability and do not implement AOT SlotSource. |

When `strict_validate_unselected == false`, precomputed reverse schema edges mark selected states/ancestors once per execution, and unselected values use `BlockCursor::skip_value(..., QueryOnly)`. Interior lexical/schema validation is intentionally absent for those values. When the selection flag is true, the same query-result APIs perform strict checking but still expose only query-result types.

## AOT adapters and compatibility notes

New public AOT interfaces:

- `SlotValues<'a>`: borrowed raw/decoded/slot/proof view.
- Sealed `SlotSource`: implemented for ABI `ValidatedSlots`, VM `BorrowedValidatedSlots`, and `BorrowedValidatedSlotsRef`. Query-only types cannot be substituted.
- `SlotReader::new(&impl SlotSource, fingerprint)` accepts both owned and borrowed strict owners.
- `BorrowedSlotReader<'a>` aliases the same checked reader, so all existing `decode_*` functions work with borrowed results.
- `decode::validate_slots` accepts any sealed SlotSource.

`SlotReader::resolve_str` keeps checked bounds and `from_utf8`, then uses `jmax_utf8::count_scalars_trusted_utf8` instead of `.chars().count()`. VM's public checked `resolve_str` does the same.

`SlotReader::values()` now returns `SlotValues<'a>` instead of `&ValidatedSlots`. Existing generated `.values().slots.len()` usage remains valid. A caller depending on `.values().payload` should use the borrowed `.values().raw` view or its original owned result.

The ABI `JsonDecode::decode_slots(&ValidatedSlots)` trait is owned by C0 and remains unchanged. Its existing generated implementations continue to accept owned results. The common AOT reader/decoder body is now usable for borrowed results without an input copy; adding a borrowed entry method to generated model implementations, or generalizing the ABI JsonDecode trait itself, requires a separate coordinator-owned ABI/codegen/derive change outside S4's exclusive ownership. S4 did not modify those files.

Dependencies: VM adds `jmax-utf8`; AOT adds `jmax-schema-vm` and `jmax-utf8`. Workspace lockfile changes, if needed, belong to C0.

## Measurement and remaining integration limits

No zero-total-allocation or speedup claim has been measured. Validation-only has no SlotValue allocation; selected slots, VM state, unknown duplicate identity, actual escaped captures, pattern execution worklists and BlockCursor's bounded discard/query stacks remain legitimate storage. In particular, the syntax worker's internal skip stack/table allocation reuse is separate from S4's reusable VM/scratch storage. Inspect allocator counters for those paths before claiming warm whole-operation allocation freedom.

The frozen cursor API has no shared VM step/cancellation callback for a long skipped span. S4 prepays input-length traversal against the VM step budget and charges VM/key/constraint operations; BlockCursor enforces its lexical/resource policies. It cannot interrupt a skip at an arbitrary external cancellation boundary without an additional cursor hook. This limitation is not hidden behind a full-document proof claim.
