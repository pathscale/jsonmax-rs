## Implemented string path

- `JsonWriter::string` and `JsonWriter::key` no longer call `escaped_string_len` or otherwise measure escaped output before writing. Values initially reserve `value.len() + 2`; keys reserve `key.len() + 2` plus their colon and any comma. Those minimum-size reservations precede punctuation or opening-quote output.
- `EscapePositions` classifies each full 64-byte block once through S1's `EscapeMasker`, borrowing `&[u8; 64]` directly. It consumes set bits using `trailing_zeros` and `mask &= mask - 1`. Only the final 0..63 bytes use a bounded scalar mask; there is no padding buffer, overread, or per-escape restart through `find_escape`.
- Each writer caches one `EscapeMasker`, including its backend capability selection, for every key/string in that message.
- The writer emits maximal ordinary UTF-8 slices across arbitrary classifier-block boundaries. Escape positions are ASCII, so emitted ordinary runs end on UTF-8 boundaries even when a code point crosses byte 63/64.
- Each encountered short escape increases the pending reservation endpoint by exactly one byte. Other controls increase it by five bytes and emit lowercase `\u00xx`. Quotes, backslashes, backspace, form feed, newline, carriage return and tab retain canonical two-byte escapes. Unicode and solidus remain unchanged.
- Public `escaped_string_len(&str) -> Result<usize>` remains available, computes `len + 2` plus escape expansion with the same cached 64-byte masks, and checks overflow. It is independent of the streaming writer.

`LimitedSink` now remembers its successful reservation endpoint. Reservations already covered by that endpoint do not delegate again; every write still checks the inclusive output allowance, host-length overflow, external errors, and exact inner-length change. `reserve_extra` extends the endpoint while including the still-unwritten suffix. This distinction matters because `ByteSink::reserve(additional)` is relative to the sink's **current** length: blindly forwarding `reserve(1)` or `reserve(5)` would fail to reserve the remaining string/closing quote/colon. For example, encoding newline plus NUL reserves endpoints 4, 5, and 10, with growth +1 and +5; the delegated relative sizes depend on bytes already emitted.

`VecSink::write_bytes` checks its limit and skips another fallible reservation when existing capacity covers the append. Writer operations retain sticky poisoning, including failures before the first write. Escape growth can now fail after an emitted prefix, as allowed by the existing direct writer contract; callers must discard that message. Existing staged typed/slot/document entry points still stage before external publication.

## Native and compatibility APIs

All functions below are public in `jmax_encode::typed`; scratch is the last argument:

```rust
pub fn write_tape_document(
    document: &jmax_dom::TapeDocument,
    sink: &mut dyn ByteSink,
    limits: EncodeLimits,
) -> Result<usize>;

pub fn write_tape_document_with_scratch(
    document: &jmax_dom::TapeDocument,
    sink: &mut dyn ByteSink,
    limits: EncodeLimits,
    scratch: &mut WriterScratch,
) -> Result<usize>;

pub fn write_borrowed_document(
    document: &jmax_dom::BorrowedDocument<'_>,
    sink: &mut dyn ByteSink,
    limits: EncodeLimits,
) -> Result<usize>;

pub fn write_borrowed_document_with_scratch(
    document: &jmax_dom::BorrowedDocument<'_>,
    sink: &mut dyn ByteSink,
    limits: EncodeLimits,
    scratch: &mut WriterScratch,
) -> Result<usize>;

pub fn write_document(
    document: &ValidatedDocument,
    sink: &mut dyn ByteSink,
    limits: EncodeLimits,
) -> Result<usize>;
```

The native functions share one `TapeView` implementation. They walk packed records through `view.nodes()`, whose O(1) steps skip key and extension words, read tags through `node.header()`, and close containers through stored parent/subtree-end links. Empty containers close immediately; a final descendant closes every ancestor ending at the same tape index. Traversal is iterative O(nodes), requires no second work stack or per-node allocation, and does not use arbitrary-ID membership scans, compatibility tables, reparsing, or a temporary output buffer. The final destination and the writer's bounded container-frame vector are the only encoder storage.

Native keys and strings resolve through `node.key()` and `node.string()`. **S3 trust-boundary detail:** public `resolve_trusted_str(StrRef)` accepts caller-constructed references and therefore still checks UTF-8. S3 explicitly directs S5 to genuine node handles for its private trusted resolver. The selected handle APIs reach `resolve_record_str` without repeated `from_utf8` or scalar counting, while preserving safe public arbitrary-reference resolution. No new unsafe block was needed in the encoder.

Native numbers use a crate-private writer entry point available only to encoder internals. It retains the exact construction-validated spelling and enforces current number/output/container limits without reparsing or UTF-8 validation. Public `number_lexeme` continues to validate arbitrary input. Native maximum depth is checked before destination access; the writer enforces current depth, per-container counts, decoded string byte lengths and number spelling lengths during emission.

Native streaming APIs return newly appended bytes and exclude any existing sink prefix from the message allowance. They may publish a partial message on any error, preserve the original external error metadata, and reclaim scratch frames on success or failure. A failed depth preflight leaves scratch untouched. The non-scratch wrappers use a fresh local `WriterScratch`; reuse the explicit scratch variants for warm encoding.

Legacy `write_document` checks the publicly mutable layout and string scalar metadata before traversal, then keeps checked string resolution and raw number validation. The existing `encode_document` and `encode_document_to_vec` remain available for `ValidatedDocument`; `encode_document` still stages output before publishing to an external sink. `ValidatedSlots` string resolution still checks bounds, UTF-8 and scalar counts; its public mutable fields never authorize trusted access.

`jmax-dom` was already a workspace dependency, so no duplicate entry was added. The encoder's `alloc` and `std` features now forward to the native DOM and string crates. In particular, `std` enables S1's runtime SIMD selection through `jmax-string/std`; alloc-only builds retain the dependencies' no_std behavior. The existing blanket unsafe prohibition was replaced with `deny(unsafe_op_in_unsafe_fn)` as requested, without adding unsafe encoder code.
