## Parsing and decoding APIs

All option-bearing native parsers enforce the caller's limits and NumericPolicy. Native construction calls S3's BlockCursor tape builder, without building legacy DocumentParts or a second DOM representation.

| API in `parse` | Contract |
| --- | --- |
| `parse_slice(input, options) -> Result<Document>` | Documented copying convenience; **now takes ParseOptions explicitly**, as requested. |
| `parse_owned(Vec<u8>, options)` | Adopts the actual Vec allocation through Payload. |
| `parse_payload(Payload, options)` | Retains the original immutable owner/range. |
| `parse_payload_with_scratch(Payload, options, &mut DomScratch)` | Returns an owned native document taking final tape/decoded buffers out of scratch. Recycle the document to recover them. |
| `parse_payload_into(&Payload, options, &mut ParseScratch)` | Preserved retained-result API; `ParseScratch` aliases native DomScratch and result borrows scratch. |
| `parse_borrowed<'a>(&'a [u8], options)` | Returns BorrowedDocument<'a> over the exact original slice, without an input copy. |
| `parse_borrowed_with_scratch<'a>(&'a [u8], options, &mut DomScratch)` | Input lifetime is independent of scratch; result takes final storage and can return it through `recycle`. |
| `parse_arc_owner<T>(Arc<T>, options)` | Uses frozen Payload::from_arc_owner, retaining the actual generic Arc<T> without a wrapper allocation or byte copy. |

| `to_legacy_document(&Document)` | Explicitly allocates compatibility parallel tables. Shares the original payload owner. |

Existing owned typed decoding now calls the direct VM's full-slot extraction helper. It remains paired with storage in `Decoded<T>`. Endpoint-message validation also explicitly requests full-slot extraction because EndpointMessage contains ValidatedSlots; it does not call the proof-only validator and then manufacture slots.

### Typed borrowed ABI integration required from C0

The actual ABI remains:

```rust
pub trait JsonDecode: Sized {
    fn decode_slots(slots: &ValidatedSlots) -> Result<Self>;
}
```

`ValidatedSlots` owns a `'static` Payload, decoded Vec and slot Vec. A caller's arbitrary `&'a [u8]` cannot safely be installed in that Payload: an arbitrary decoder can clone/retain it after the call. S4's AOT reader accepts borrowed strict slot owners, but the unchanged ABI trait and current derive/codegen implementations expose no method by which this generic facade can invoke that borrowed reader. Changing only jsonmax cannot bridge that trait without copying, changing trait bounds, or fabricating ownership/lifetimes.

Implemented exact requested generic functions:

- `from_borrowed<'a, T: JsonDecode + SchemaProvider>(&'a [u8], ParseOptions) -> Result<T>`.
- `from_borrowed_with_schema<'a, T: JsonDecode + SchemaProvider>(&'a [u8], &CompiledSchema, ParseOptions) -> Result<T>`.

They first execute strict extraction on the original borrowed slice, then make **one explicit fallible input copy** for the existing owned decoder; decoded and slot Vecs move without copying. The no-schema variant recompiles because its requested bounds do not include `'static`, which the existing TypeId cache needs. The copy and compilation behavior are documented at both functions. T's decoder remains responsible for retaining any storage its returned representation needs.

C0 must add a borrowed slot-view decoding contract in `crates/jmax-abi` and implement it in derive/codegen (and connect that view to S4's checked AOT reader), then change these two facade functions to invoke it. Those paths are outside S6 ownership. Keep handwritten decoder compatibility explicit; do not silently assert that an arbitrary owned-only JsonDecode implementation can consume borrowed storage. The test `typed_borrowed_compatibility_adapter_owns_its_explicit_input_copy` deliberately records today's adapter; replace its copy assertion with the new contract's behavior once that bridge lands. Until then, use `endpoint::extract_borrowed` / `extract_borrowed_with_scratch` with S4's borrowed AOT SlotReader for actual no-input-copy decoding.

## Direct schema validation and extraction

`endpoint::validate_payload(Payload, &CompiledSchema, options) -> Result<ValidationProof>` now routes through `direct::validate_payload_direct`. `validate_payload_with_scratch(Payload, &CompiledSchema, options, &mut ValidationScratch)` uses `direct::validate_into`. Neither requests a Selection or captures SlotValue output. `endpoint::validate_borrowed(&CompiledSchema, &[u8], options, &mut ValidationScratch)` uses `direct::validate_borrowed_into`. Capability fields are not exposed as skip authorization by these proof-only facade functions.

Strict extraction is a distinct path:

- Existing `extract_payload` calls `direct::extract_payload_direct` and preserves its prior caller-selection-order result, including repeated selection fields.
- `extract_payload_into` and its new `extract_payload_with_scratch` spelling call `direct::extract_payload_into`, then reuse `ValidationScratch::order_selection`.
- `extract_borrowed(schema, selection, bytes, options)` returns `jmax_schema_vm::BorrowedValidatedSlots<'a>` directly, retaining compiled slot indices for borrowed AOT readers.
- `extract_borrowed_with_scratch<'raw, 'scratch>(schema, selection, bytes, options, scratch)` returns `BorrowedValidatedSlotsRef<'raw, 'scratch>`. Its two lifetimes separately prevent input expiry and scratch reuse while decoded/slot references remain live.
- Borrowed strict and query results use **compiled slot indices**, with Empty for absent/unselected fields, as specified by S4; owned legacy facade selected extraction remains in caller selection order. This distinction is documented.
- `validate_payload_into` keeps its historic full-slot-producing signature for existing typed/warm callers. Its doc explicitly identifies it as extraction and directs proof-only callers to `validate_payload_with_scratch` / `validate_borrowed`. It uses the direct extractor, never EventInput/CursorInput.

`extract_query_payload` and `extract_query_borrowed` build a small fallibly allocated field-id selection with `strict_validate_unselected: false`, regardless of the incoming flag, and call S4's query-only direct entry points. They return QuerySlots / BorrowedQuerySlots without ValidationProof or ValidationCapability. `query_extract_borrowed` aliases the latter spelling from the ownership contract. Strict extraction still rejects a false strict flag; it never upgrades a structural skip into validated slots.

## Borrowed path queries

Added root `BorrowedQueryResult<'a>` with `raw`, `matches`, `fully_validated`, and lifetime-preserving `raw_match` accessors. `query::execute_borrowed(query, bytes, QueryOptions)` uses S2's `walk_borrowed_with_numeric` over its persistent BlockCursor and returns raw span matches into exactly those bytes. It constructs no input owner, DOM, whole-input index or token Vec.

Removed the prior unconditional native-DOM prevalidation from `query_payload`. Owned queries now execute the same borrowed selector core and retain their original Payload in QueryResult. Existing query_slice remains an explicitly copying convenience.

For containers with no selector descendants, the selector calls `skip_current(StrictValidate)` in strict mode and `skip_current(QueryOnly)` in query mode for unselected values. Selected complete containers always receive strict validation. A `strict_subtree` frame flag propagates that requirement to descendants when a path selects both a container and a deeper value; a selected parent can never contain a lexically invalid skipped child. Selected raw spelling, repeated paths, caller path order, absent paths, array indices, total max_matches, numeric policy and trailing validation are retained. Query mode always returns `fully_validated: false` and neither result type issues a proof.

The event cursor still validates outer keys and encountered scalar tokens, including some unselected scalars. Query-only relaxed validation applies to structurally skipped container interiors; this facade does not claim every unselected scalar avoids lexical decoding.

## Native and borrowed encoding

The facade no longer traverses legacy `.parts()` or per-node metadata and no longer reparses native number spellings:

- `encode_document` / retained `document_to_vec` emit native tape into the final OutputBuffer using `typed::write_tape_document`.
- `encode_document_to_sink` stages native output before destination publication.
- `encode_borrowed_document` / `encode_borrowed_document_to_sink` provide matching borrowed tape output via `typed::write_borrowed_document`.
- `encode_document_streaming` and `encode_borrowed_document_streaming` emit directly without an intermediate output Vec. Errors may leave a partial message; byte allowances exclude any existing destination prefix.
- `document_to_buffer` and `borrowed_document_to_buffer` use S5's native scratch entry points so writer frames can be retained; they clear the logical final output first and may leave a partial result on error.
- New `to_sink_streaming` invokes JsonEncode directly through jmax_encode::LimitedSink. Its JsonEncode contract and partial-output behavior are documented.
- Existing `to_sink` still stages completely before making any destination call. Encoding failure leaves the destination untouched; as before, an external sink's own write failure can leave a prefix after publication begins. No generic ByteSink can roll back that external side effect.
