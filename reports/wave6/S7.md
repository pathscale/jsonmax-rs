## jmax-nagoya

### Bounded reactive hosted lane

Added `src/reactive.rs`, enabled by the existing `nagoya-rt` feature:

- `ReactiveRing<T>` reserves a fixed logical queue capacity fallibly, uses a
  `VecDeque` ring, and waits for readiness/capacity through nagoya notifications.
  Waiters register before inspecting queue state; locks are dropped before
  notification waits and before dropping queued user values. No idle/capacity
  spin-poll loop was added.
- `HostedPool::<V>::new(job_capacity, completion_capacity, first_sequence)`
  returns producer/completion and unique worker endpoints. Both capacities must
  be nonzero. `HostedWorker::spawn_on(&Runtime)` schedules the worker on an
  explicitly supplied nagoya runtime; hosts can alternatively await `run()`.
- Each queue entry moves the entire `Submission`: owned `ParseJob` payload,
  cancellation token, `Arc<V>` validator/schema handle, and unique scratch /
  admission lease. Reactor-local handles and borrowed payloads do not enter it.
- A lane has one worker. Concurrent producers serialize sequence assignment and
  enqueue, and increment only after successful enqueue; rejection, cancellation,
  or dropping a pending submission creates no sequence gap. Successful and
  failed completions remain FIFO. Multiple independent lanes can run in parallel;
  this implementation does not claim a parallel worker pool with global ordering.
- Job and completion queues each apply backpressure. At most one additional
  job/result is in the worker between those rings. Pending producers also own
  their admission leases, so admission bounds outstanding request storage.
- Cancellation wakes a submitter waiting on sequence assignment or job capacity.
  Accepted cancelled jobs generate error completions at their original sequence.
  Cancellation while a successful completion waits on capacity drops its
  payload/lease and replaces it with a positional cancellation error.
- Successful completions hold `Admitted<ValidatedSlots>` until the consumer
  drops it or transfers `(value, lease)` using `into_parts()`. Validation errors
  release the submission's lease once. Queue rejection drops the whole pending
  aggregate. No admission lease is cloned or manually released.
- `close()` and endpoint/worker Drop are terminal shutdown, wake blocked work,
  and permit discarding accepted sequences. Close drains queued values when
  its queue lock is immediately available; otherwise receive/final drop drains
  them. Pending futures must be polled or dropped to run their own cleanup.
  Ordinary per-job cancellation preserves sequence completions; shutdown is an
  explicit stream termination. Dropping a nagoya join handle detaches it, per
  nagoya's existing contract; use pool close or handle cancellation to stop it.

### Compiled schema and redundant payload scan

Added `worker::SchemaValidator`, which owns `Arc<jmax_schema_vm::ValidatedProgram>`,
an immutable strict selection, numeric policy, and a finite VM step limit. It
implements `ParseValidator` using the direct owned schema VM. The VM receives
the supplied scratch limit, and its output passes retained-storage checks.
Unused generic syntax scratch is freed before allocating VM scratch. Cancellation
is checked before/after the synchronous VM turn and before publication; there is
no claim of instruction-level cancellation inside that synchronous VM call.

`submit::check_output` now bypasses the full-payload comparison when:

1. `output.payload.shares_backing_with(original)` is true;
2. visible byte pointers are equal; and
3. visible lengths are equal.

Proof payload/decoded lengths are still checked. Custom validators that replace
backing still receive the defensive byte-for-byte comparison, including rejection
of equal-length different bytes. This uses the frozen contract's backing/range
identity alternative. `ValidatedSlots` has no `ValidationCapability` field, so
no capability is invented or reconstructed from proof metadata.

### Retained backing accounting

Added `admission::{payload_retained_bytes, handoff_backing_bytes}` and
`Admission::try_parse(payload, additional_retained_bytes, scratch_bytes)`.
Preflight checks the payload's full known backing lower bound rather than just
the visible JSON length. Output accounting includes decoded and slot capacities.
Coexisting request/result owners sharing backing charge the larger backing
lower bound once; different allocations charge the sum during handoff.

The accounting policy is per-job conservative reservation. Independent requests
sharing an owner each reserve their own worst-case retention; this is not a
global allocation registry. The immutable compiled schema/selection and bounded
queue infrastructure are host-owned shared infrastructure outside those payload
reservations. Caller-declared extra retention must cover typed private allocations.
`Bytes` exposes only visible length through the ABI; hidden backing capacity
cannot be measured by this adapter. Arc-backed views retain and charge the known
whole byte backing, subject to the ABI's lower-bound semantics.

## HTTP and WebSocket handoff

Added `jmax-http::body`:

- `receive_bytes`, `receive_arc_owner`, checked `subview`, and combined
  `receive_bytes_subview` / `receive_arc_subview` preserve the transport owner.
- `response_job` checks complete response metadata before moving the body to a
  `ParseJob`; `request_job` checks request metadata and optional webhook
  authentication before moving the body. Hosts retain routing metadata
  separately before consuming the incoming request.
- Existing executor-neutral `incoming::decode_on` remains available.

WebSocket changes:

- Close reasons use `Payload::slice`, preserving `Shared`, `SharedView`, and
  `Bytes` allocations instead of copying Arc reasons.
- Added `receive::{receive_arc_owner, receive_payload, receive_subview,
  into_parse_job}` alongside the existing `receive_bytes`. These still enforce
  complete-message opcode, UTF-8, and configured byte policies.
- Added `send::OutboundFrame`: owns both validated source and already encoded
  transport bytes, exposes the remaining borrowed/owned subview, and advances a
  checked offset for actual write progress. Zero writes retain state; excessive
  progress fails without advancing. The transport supplies matching encoded wire
  bytes (including headers/masking as necessary); the cursor performs no encoding
  or socket I/O. It does not add a new WebSocket encoder.
- Bridge retained-budget checks now use backing-byte lower bounds.
- HTTP/WSS validator boundary checks use the same exact-owner/range shortcut,
  preserving byte-comparison fallback for replacement owners and proof checks.

No fragment-assembly, unmasking, compression, TLS, or kernel-copy elimination is
claimed. Existing fragmented-message assembly still copies as required.
