## Implementation

`Cargo.toml` retains package `ps-pikkr`, version `0.16.1`, and now explicitly declares:

```toml
[lib]
name = "pikkr"
path = "src/lib.rs"
```

Rust 2015 is explicit to retain upstream module import semantics. The obsolete optional nightly `x86intrin` dependency is removed. The standalone Cargo.lock now contains only `fnv` 1.0.7 and ps-pikkr; its ignore rule was removed so it can be preserved with the fork. `avx-accel` remains an accepted compatibility flag; native dispatch is automatic when portable is disabled.

The architecture cfgs in lib.rs and index_builder.rs now select exactly one backend:

| Architecture/features | Selected implementation |
| --- | --- |
| Any architecture, `portable` enabled (including with `avx-accel`) | Emulated scalar module only |
| aarch64, portable disabled | NEON; PMULL prefix when `aes` is detected |
| x86_64, portable disabled | Stable stdarch AVX2 classifier when available; bounded scalar compatibility fallback otherwise |
| Other architectures, portable disabled | Emulated scalar module |

Audited every cfg in `src/{lib,pikkr,index_builder,parser,query,bit,avx,neon,emulated,utf8,error,result}.rs`. Architecture selection/imports and prefix dispatch are confined to lib/index_builder. pikkr/parser/query have only test-module cfgs; bit additionally gates its now test-only obsolete `s` helper. neon has its test module and runtime-checks PMULL before its intrinsic test. avx/emulated/utf8/error/result have no competing architecture cfgs. No avx-accel condition imports x86 symbols on ARM, and portable excludes both native modules. Minor existing trait-object/lifetime warnings were fixed without changing query behavior.

The NEON 64-byte indexer loads two 32-byte groups, four `vld1q_u8` loads total, directly from full input blocks and derives backslash, quote, colon and object-brace masks from those registers. Full blocks are not copied into a staging buffer. `vmull_p64(bits, !0u64)` computes quote prefix parity in `#[target_feature(enable = "neon,aes")]`; entry is guarded by `is_aarch64_feature_detected!("aes")`. A six-shift prefix implementation remains available when PMULL is absent and for portable builds. The native and scalar prefixes are differentially tested.

The rewritten x86 implementation uses `core::arch::x86_64`. Its AVX2 classifier loads two input registers per full block after one availability check per classification call. PCLMULQDQ detection and its target-feature function are separate from AVX2. Short tails are copied into a fixed zero pad; full blocks are read directly. The compatibility vector interface uses bounded scalar operations if AVX2 is unavailable. This path has been cross-checked, not executed on x86 hardware.

Quote filtering now uses word-level backslash run starts, alternating parity masks, wrapping carries, and incoming/outgoing run parity. It preserves odd runs ending at byte 63, including runs crossing several all-backslash blocks, so an escaped quote at the next block's byte zero does not toggle string state. This also correctly retains a genuine quote at input byte zero. The prior two temporary quote-work vectors and reverse per-quote backslash rescans are eliminated. String parity carries between blocks and retains upstream outside-mask conventions.

Tail loaders assert their bounds and never load beyond the provided slice. NEON tails use a 32-byte zero pad; full blocks use direct loads. Empty inputs and every 0..63-byte short tail, exact 32/64-byte lengths, and multiple full blocks followed by tails are exercised. Native and portable guard-page tests place the input immediately before a PROT_NONE page.

## Semantic and measurement scope

ps-pikkr selects borrowed raw values using object-field paths and materialized bitmap/per-depth Vec indexes. It is **query/selection, not full validation** and never issues jsonmax validation proof. Arrays can be selected as complete raw values, including nested arrays and objects; array indexing, wildcard traversal and schema enforcement are unsupported. Dot-separated object keys are compared as raw bytes. Valid Unicode keys/values work, but escaped spellings are not normalized and selected strings are not decoded.

Missing fields return None. Some malformed structures return InvalidRecord, as the historical issue tests demonstrate, but success does not establish complete grammar, UTF-8, escape/number validity, duplicate-key policy, absence of trailing junk, or validity of unselected content. A regression deliberately selects `"\\u0061"` while accepting an invalid unselected atom; consumers receive the original raw spelling. Duplicate-field selection is not a defined supported contract.

Trained speculation compares the actual field bytes before using a learned position and falls back for changed shapes/order. Trained and untrained selection must be reported separately; benchmark training must occur outside measurement and selected values must be observed. Bitmap/depth indexes, learned-position sets, per-result Vec allocation, and returned borrowed input retention remain part of this competitor's memory costs. It is not jsonmax's zero-intermediate-index-buffer architecture and should not be compared to strict schema validation as equivalent work. Upstream nightly benches remain historical harnesses; ordinary library tests use stable Rust.

No background build or benchmark process remains from S8.
